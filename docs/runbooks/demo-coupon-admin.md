# MSA 고도화 시연 런북 — 쿠폰 · 관리자 화면(리포트 다운로드·통계 그래프) (WBS 6.5.2c)

> 2026-11-27 · 한채연. 통합 시연 11/27(M11, ADR-114). 증명할 것: **관리자가 `/admin`에서 VIP 선착순 쿠폰 이벤트를 열면 사용자 화면에 바로 뜨고, VIP만 수량 안에서 받는다**(ADR-118) · **오류·보안 로그를 날짜별 CSV로 내려받고, AI가 답하지 못한 질문을 분류별 그래프로 본다**(ADR-120·121).
> 화면만 다룬다. 쿠폰을 쓴 체크아웃(6.5.2a, 남궁일) · 서비스 정지/가동·AZ 장애(6.5.2b, `demo-msa.md`) · AI 챗봇(6.5.2d)은 각 담당 대본. 리포트·ops-api의 근거·문제 해결은 `terraform-infra.md` 6-L·6-M, 그룹 지정은 7-6-5.

---

## 0. 원칙

| 원칙 | 내용 |
| --- | --- |
| 계정 3개, 창 3개 | ① 관리자(`ADMIN` 그룹) ② VIP(`VIP` 그룹) ③ 일반. 토큰은 탭 메모리에 있지만 Cognito 로그인 세션(쿠키)은 브라우저 하나에 하나라 **브라우저 프로필(또는 다른 브라우저)을 계정마다 따로** 쓴다. 시크릿 창 하나로 두 계정을 번갈아 쓰지 않는다 |
| 계정 정보는 화면에 안 낸다 | 이메일·`sub`를 녹화·문서·PR에 남기지 않는다. 헤더의 이름은 시연용 이름으로 미리 바꿔 둔다(마이페이지 프로필 수정) |
| 이벤트는 하나씩 | coupon은 끝나지 않은 이벤트와 기간이 겹치면 400 `EVENT_OVERLAP`. 리허설 이벤트는 **본 시연 전에 끝나도록** 짧게(진행 5분) 만든다 |
| 겹치지 않는다 | 6.5.2b(정지/가동)가 coupon을 멈춘 동안에는 장면 A를 하지 않는다. AI 통계(장면 C)는 `ng-ai`를 켜야 하므로 **실시간 좌석 장면과 같은 시간대면 빼고**(좌석 데모 중 `ng-ai` 0대 — CLAUDE.md 절대 규칙) 녹화로 대신한다 |
| 녹화 | 리허설 1회를 녹화해 둔다(본 시연이 막히면 그 영상으로 — 5장) |

## 1. 준비

### 1-1. 하루 전·T-60분

- [ ] 그룹: 관리자 계정은 `ADMIN`, VIP 계정은 `VIP`(7-6-5). 일반 계정은 어느 그룹에도 없다. 지정 뒤 **로그아웃 → 다시 로그인**(그룹은 토큰 재발급 뒤 반영)
- [ ] coupon이 떠 있다: `/admin/services`에서 coupon Ready 2/2, 정지 기록 없음
- [ ] 리포트가 쌓여 있다: `/admin/reports` 날짜 목록에 **오늘**이 있다. 없으면 오류 줄을 일부러 만들고(아래) 내보내기를 한 번 돌린다(6-M 2 — 관리자)

```bash
# 토큰 없이 선점 → gateway SECURITY 401 로그 몇 줄 (사용자 데이터에 영향 없음)
for i in 1 2 3 4 5; do curl -s -o /dev/null -w '%{http_code}\n' -X POST "https://<도메인>/api/seats/hold"; done   # 401 ×5
# 차단 경로 → SECURITY 404
curl -s -o /dev/null -w '%{http_code}\n' "https://<도메인>/api/internal/screenings/1"                            # 404
# 10분 안에 CronJob이 옮긴다. 급하면 관리자가 6-M 2) 수동 실행
```

- [ ] AI 통계(장면 C를 할 때만): 김서현과 시간을 맞춰 `ng-ai`를 켜고(6-G) ai가 `APP_AI_DATA_SOURCE=db`인지 확인. 일반 계정으로 범위 밖 질문을 5~6개 미리 보낸다(예: 「예매 취소해 줘」, 「주차장 있어?」, 「아무 영화나 추천해 줘」, 「오늘 날씨 어때」) → `/admin/ai-demand` 「최근 7일」에 막대가 보인다. **좌석 데모 시간에는 하지 않는다**

### 1-2. T-15분 — 화면 탭

| 창 | 계정 | 탭 |
| --- | --- | --- |
| A | 관리자 | `/admin`(개요) · `/admin/coupons` · `/admin/reports` · `/admin/ai-demand` |
| B | VIP | 메인 `/`(쿠폰 배너) |
| C | 일반 | 메인 `/`(쿠폰 배너) |

- [ ] 창 A 화면 확대 125%, 창 B·C는 나란히 — 배너 숫자가 같이 줄어드는 것이 보이게
- [ ] 내려받은 CSV를 열 프로그램(스프레드시트 또는 텍스트 편집기) 하나 열어 둔다. 다운로드 폴더에 다른 파일이 보이지 않게 정리

## 2. 장면 A — 쿠폰 이벤트 열기 · VIP 선착순 (약 4분)

| 시간 | 화면 | 조작 | 말 |
| --- | --- | --- | --- |
| 0:00 | A `/admin/coupons` | 「쿠폰 이벤트 만들기」 — 제목 `시연 VIP 20%`, 할인율 `20`, 수량 `2`, 시작 = **지금 + 2분**(KST), 진행 시간 `10`분 → 만들기 | 「관리자 화면은 gateway를 거치지 않고 ops-api로 들어오고, ops-api가 coupon 내부 API로 이벤트를 만든다」 |
| 0:30 | A | 목록 맨 위에 새 이벤트(예정) | 「수량은 coupon DB가 원본이고, 선착순 차감은 Valkey에서 한다」 |
| 0:45 | B · C | 메인 배너 「선착순 쿠폰 오픈 예정」 · 「시작까지」 카운트다운 · B 버튼 「곧 시작해요」, C 버튼 「VIP 전용」 | 「등급은 Cognito 그룹 → gateway가 `X-User-Grade`로 붙인다. 일반 회원은 볼 수만 있다」 |
| 2:00 | B · C | 배너가 「선착순 쿠폰 진행 중」 · 「남은 쿠폰 수량 2」 | — |
| 2:10 | C | 버튼이 「VIP 전용」(눌리지 않음) · 「VIP 회원만 받을 수 있어요」 | 「서버도 막는다 — 직접 불러도 403 `COUPON_NOT_ELIGIBLE`」 |
| 2:20 | B | 쿠폰 받기 → 「쿠폰을 받았어요! 결제할 때 쓸 수 있어요.」 · 수량 1 | 「한 명에 한 장, DB 유일 제약이 마지막 방어선」 |
| 2:40 | B | 새로고침해도 「받은 쿠폰이에요」 · 「내 쿠폰 보기」 → 마이페이지 쿠폰 탭 | 「같은 요청이 두 번 와도 한 장만 나간다(멱등 키 + DB 유일 제약)」 |
| 3:00 | A | 목록 새로고침 — 「발급/수량」 1/2 · 「남은 수량」 1 | 「관리자 화면에서 발급 현황을 본다」 |
| 3:20 | B | (6.5.2a로 넘김) 결제 화면 쿠폰 선택에 방금 받은 쿠폰이 보인다 | 「이 쿠폰으로 체크아웃하는 장면은 다음 순서」 |

- 수량을 2로 두는 이유: 남은 1장으로 「모두 소진됐어요」를 보여 줄 수 있다 — 두 번째 VIP 계정이 없으면 말로만
- 시작을 「지금」으로 두면 1분만 넘어도 400 `STARTS_IN_PAST`가 난다. 2분 뒤로 두고 그동안 0:30~0:45 설명을 한다
- 시연 뒤 이벤트는 10분이면 끝난다 — 다음 시연(6.5.2a 쿠폰 체크아웃)이 같은 이벤트의 쿠폰을 쓰면 **종료 전에** 체크아웃까지 끝내야 한다(종료 스윕이 ISSUED를 EXPIRED로 바꾼다). 6.5.2a 담당과 순서·진행 시간을 맞춘다

## 3. 장면 B — 오류 리포트 다운로드 (약 3분)

| 시간 | 화면 | 조작 | 말 |
| --- | --- | --- | --- |
| 0:00 | A `/admin/reports` | 「오류 리포트 — 오류·보안 로그를 날짜별 CSV로 내려받아요」, 날짜 드롭다운에서 **오늘** | 「모든 서비스가 오류·보안 로그에 `errorCategory`를 붙인다. Loki → 10분마다 S3로 옮기고 Glue·Athena로 묻는다」 |
| 0:20 | A | 「리포트 만들기」 → 「리포트를 만드는 중이에요 (Athena 쿼리)」 → 몇 초 뒤 행 수·「12:34에 만듦」·내려받기 | 「같은 날짜를 1시간 안에 다시 누르면 쿼리를 다시 돌리지 않는다. 새 로그가 옮겨졌으면 다시 만든다」 |
| 1:00 | A → CSV | 내려받기 → CSV 열기. 열 `timestamp·service·level·errorCategory·status·path·traceId·message` | 「아까 토큰 없이 부른 401이 `SECURITY`로, 막힌 `/api/internal` 이 404로 남았다. IP·토큰·userId 열은 없다」 |
| 2:00 | CSV | `traceId` 하나 짚기 | 「traceId로 Grafana에서 그 요청의 서비스 로그를 다 따라간다」(시간이 남을 때만 Grafana Explore) |
| 2:30 | A | 내려받기 주소 아래 「주소는 5분 동안만 쓸 수 있어요」 | 「S3 presigned URL 5분 — 링크가 새도 오래 못 쓴다」 |

- 리포트는 최대 약 10분 늦다(「로그는 10분마다 옮겨져…」 안내). 장면 직전에 만든 오류는 안 보일 수 있으니 오류 만들기는 1-1에서 미리
- 행 수 0이면 「이 날짜에는 기록된 오류가 없어요(빈 CSV)」 — 1-1의 오류 만들기를 빠뜨린 것. 어제 날짜로 바꿔 보여 준다

## 4. 장면 C — AI 범위 밖 질문 그래프 (약 2분, `ng-ai`를 켤 수 있을 때만)

| 시간 | 화면 | 조작 | 말 |
| --- | --- | --- | --- |
| 0:00 | A `/admin/ai-demand` | 「최근 7일」 — 모두 N건 · 분류별 가로 막대(기능 실행 요청 · 사이트 이용 문의 · 영화 추천 · 서비스와 무관) | 「챗봇이 답하지 못한 질문을 ai가 자기 DB(`ai_db.unmet_demand`)에 분류해 둔다」 |
| 0:40 | A | 「많이 나온 요청 (상위 10)」 | 「질문 원문·사용자 ID는 저장하지 않는다. Claude가 쓴 한 줄 요약과 횟수만」 |
| 1:20 | A | 「최근 30일」로 바꿔 보기 | 「이 숫자가 다음에 만들 기능의 근거 — 많이 나온 요청을 기능 제안서 초안으로 묶는 워크플로우(6.4.8)로 이어진다」 |

- 「통계 없음 — AI 서버(ai)에서 통계를 받지 못했어요」가 뜨면 `ng-ai`가 꺼져 있거나 ai가 `snapshot` 모드. 장면을 넘기고 녹화로 대신한다
- 막대가 1~2개뿐이면 1-1의 질문을 분류가 다르게 더 보낸다(인사·잡담은 세지 않는다)

## 5. 끝내기 (시연 직후)

- [ ] 쿠폰 이벤트는 진행 시간이 지나면 저절로 끝난다 — 지울 것 없음. 다음 이벤트를 바로 만들어야 하면 종료 시각이 지났는지 `/admin/coupons`에서 확인
- [ ] `ng-ai`를 장면 C 때문에 켰으면 김서현과 확인 뒤 끈다(6-G, `cluster-scale.sh down ng-ai`)
- [ ] 내려받은 CSV는 시연 PC에서 지운다(로그 메시지가 들어 있다)
- [ ] 노션 6.5.2c에 녹화 링크·소요·막힌 곳, `terraform-infra.md` 14장에 한 줄

## 6. 막힐 때

| 상황 | 대신 할 것 |
| --- | --- |
| `/admin` 「관리자 권한이 필요해요」(403) | 관리자 계정 로그아웃 → 다시 로그인(그룹은 토큰 재발급 뒤, 7-6-5) |
| 이벤트 만들기 400 `EVENT_OVERLAP` | 끝나지 않은 리허설 이벤트가 있다 — 목록에서 종료 시각 확인, 그 뒤로 시작을 미룬다 |
| 이벤트 만들기 503 | 만들어졌을 수 있다 — **목록부터 확인**하고 없을 때만 다시 만든다(계약: 503은 결과 불확실) |
| VIP 계정 배너에 「VIP 전용」 | 그룹 지정 뒤 다시 로그인하지 않았다 → 로그아웃·로그인 |
| 배너가 안 뜬다 | 이벤트 시작 전·후인지 확인. coupon 정지 중이면(6.5.2b) 가동 뒤 |
| 리포트 날짜 목록이 비어 있음 · 503 `REPORT_UNAVAILABLE` | 6-M 증상 표. 시간이 없으면 녹화 영상으로 |
| 리포트가 2분 넘게 「만드는 중」 | 「리포트가 오래 걸리고 있어요」 → 다시 만들기 1회, 안 되면 녹화 |
| CSV 내려받기가 XML 오류 | 주소가 5분 지남 → 「새 주소 받기」. 리전 오류면 6-M 증상 표 |
